02配置到 Agent 应用：两种语义

「Agent 应用」有两种方向，配置清单完全不同，先对号入座。

目标：可观测 + 评估 + prompt 管理。需要 4 样东西。

① 凭据三件套（唯一必填）

LANGFUSE_PUBLIC_KEY="pk-lf-…"
LANGFUSE_SECRET_KEY="sk-lf-…"
LANGFUSE_BASE_URL="https://cloud.langfuse.com"

② SDK

# Python
pip install langfuse

# JS / TS
npm i @langfuse/openai @langfuse/tracing @langfuse/otel

③ 埋点代码（三选一）

from langfuse import observe
from langfuse.openai import openai

@observe()
def main():
    openai.chat.completions.create(
        model="gpt-4o",

B · 把 Langfuse 接给「Coding Agent」

目标：让 agent 自己查 trace、管 prompt、跑评估。三条等价通道，按 agent 能力选一条。

通道适用装法
Agent Skill 要 agent 掌握完整最佳实践 npx skills add langfuse/skills --skill "langfuse"
CLI agent 能跑 bash，可先预过滤再进上下文 npx @langfuse/cli api <resource> <action>
MCP server agent 不能执行 shell 命令 POST /api/public/mcp

MCP 客户端配置

{
  "mcpServers": {
    "langfuse": {
      "url": "https://cloud.langfuse.com/api/public/mcp",
      "transport": "streamableHttp",
      "headers": {
        "Authorization": "Basic <base64(pk:sk)>"
      }
    }
  }
}
echo -n "pk-lf-xxx:sk-lf-xxx" | base64

claude mcp add --transport http langfuse \
  http://localhost:3000/api/public/mcp \
  --header "Authorization: Basic {base64}"

CLI 环境变量（注意命名不同）

LANGFUSE_PUBLIC_KEY=…
LANGFUSE_SECRET_KEY=…
LANGFUSE_HOST=…   # CLI 用 HOST，SDK 用 BASE_URL

只读 agent

MCP 工具注解带 readOnlyHint / destructiveHint， 只放行查询类工具即可禁写。

03自托管运行时拓扑

一条 trace 从 SDK 到 OLAP 的完整链路，以及四个存储各管什么。

主链路：埋点上报 → web → worker → 存储 请求 / 调用关系 普通服务

04运行时调用链

一条 trace 在系统内部的流转顺序，对应排查「数据没上来」时的定位路径。

agent.app └─ SDK @observe() → batch queue └─ POST /api/public/ingestion (Basic auth: pk/sk) └─ langfuse-web ├─ 校验 key → 解析 project ├─ 写 Redis（ingestion queue） └─ langfuse-worker 消费 ├─ 写 ClickHouse（observations / traces / scores） ├─ 写 Postgres（数据集 / prompt / 配置） └─ 写 S3（媒体、批量导出） └─ UI：Traces / Observations / Scores

05坑位清单

照着抄最容易翻车的 8 个点。

01MCP 只支持 project-scoped key
组织级（org-level）key 会被直接拒绝 —— 换 key 不是换 URL。
02CLI 用 LANGFUSE_HOST，SDK 用 LANGFUSE_BASE_URL
两个名字不同，混用会静默失败、不报错。
03反代场景要配 LANGFUSE_MCP_ALLOWED_HOSTS
MCP 会校验请求 Host，不一致即拒；填 * 能过但不推荐。
04自托管必须换掉所有 CHANGEME 密钥
尤其 ENCRYPTION_KEY —— 上线后不能改，改了历史数据解不开。
05JS/TS 的 OTel 要显式初始化
不注册 LangfuseSpanProcessor 就不会上报，span 静默丢失。
06BASE_URL 必须与账号区域一致
填错表现为「key 无效」而不是明确报错，最难查的一类。
07MinIO / S3 兼容要 FORCE_PATH_STYLE=true
否则路径式访问失败，报 404 类错误。
08本地开发的 ingestion 队列有延迟
SDK 集成测试要调小 LANGFUSE_INGESTION_QUEUE_DELAY_MS，否则断言时数据还没落库。

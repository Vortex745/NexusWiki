## 执行与验证约定

1. 领取前阅读总规格和前置票，确认它们的验收证据；实际状态以任务票、清单和验证记录一致为准。
2. Bug 先复现。首张基线票可以验收“已证实当前失败”，不能把这些观测写成修复通过。
3. 主要测试入口是既有文件上传、任务状态和恢复 HTTP 接口，以及摄取生命周期；独立真值所需解析/产物测试作为补充。第二批补真实组件和浏览器验收。
4. 只修改本票负责的行为和必要契约，保留已有用户改动。完成后更新本地票、plan.json、progress.md 和 verify.json；本轮不提交代码。
5. 无法证明缓存兼容时从保留原文件重跑。复杂内容缺少能力时保留待校验；任何速度优化不得放宽完整性。

Jev 本轮实际模型 `jev-1.13.0`，推荐 16 票、共享门槛下分开验证完整性与索引、先建立基线。三项选中选项的概率均为 1.00；这只表示给定候选的模型选择分布，不是可行性概率或实测成功率。

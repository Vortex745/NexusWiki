建议顺序：**PL-01 → PL-02 → PL-03 → PL-04 → PL-05 → PL-06**。PL-01优先保护发布，PL-02补齐用户请求的来源，PL-03先止住纠错预算饥饿，PL-04修正材料与测量，PL-05补实际上下文观测，PL-06消除PageIndex范围内召回损失。

技术依赖只有**PL-04 → PL-05**，因为PL-05消费PL-04提供的实际装配/压缩输出来源结果。技术上无前置的是PL-01/02/03/04/06；它们仍需用户实施指令。优先顺序不作为强制依赖，共同模块调整应串行协调。当前不启动子代理或自动实施。

## 验收边界

已由用户确认沿用现有边界：共享Answer入口、真实Chat HTTP的SSE/JSON、真实会话消费、捕获实际生成payload；PageIndex以真实SQLite仓储和搜索边界补充。外部模型与服务使用可重放夹具，真实服务全链路和质量基准单列，不作为本轮规格校验已通过事项。

不增加专门的测试mock入口，不用最终引用推断上下文顺序。PL-01关键用例接真实runner及事件adapter，PL-03/04/05校对实际模型输入，PL-06实际执行仓储筛选。

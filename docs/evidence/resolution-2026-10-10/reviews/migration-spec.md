# Migration spec review

Reviewed `git diff 36b8faad...1975ce1749ebdf71e71ccbc72974d821ddd95c5b` for `src/ingestion/storage/chunk_index_migration.ts`, `scripts/migrate-chunk-index.ts`, and migration tests against approved plan §4. No business writes or private document/.env reads.

- **[P1] Freeze does not await existing writers** — `chunk_index_migration.ts:176`. Spec: “源写锁防止遗漏其他写入者.” Updating `index.blocks.write` through `putSettings` is not the barrier supplied by the Add index block API, which waits for in-flight writes. An already accepted update can finish after the source manifest and reindex snapshot; both old snapshots agree, yet cutover loses the late source update. Use `indices.addBlock({ index: source, block: "write" })`, require block/shard acknowledgment, then refresh and scan. Apply the same barrier before target verification. Add a delayed-writer negative control. Root must still drain known worker/sync processes.

- **[P2] Ambiguous lock acknowledgment escapes rollback** — `chunk_index_migration.ts:176–177,209`. Spec: “撤销本脚本新增的源 write block，恢复原设定.” The `locked` flag is set only after the mutation returns. If ES applies the block but its response times out/disconnects, catch skips restoration, leaving the source unexpectedly frozen; CLI failure report also omits that state. Track the mutation attempt before awaiting it and attempt original-state restoration on error; preserve an explicit restoration failure and final block state in diagnostics. Test a fake that applies the block and then rejects.

Other reviewed safeguards are present: no overwrite/delete, stored source/vector checks, source canonical hashes, three float leaves/docvalues checks, ID/count reconciliation, PIT cursor updates/closure, original lock restoration on ordinary copy/verification failure, and retained target. Existing tests cover ordinary corruption, reindex failure, dimensions, target collision and legitimate unembedded parents, but not the two failure modes above. Routing assertions use a fake that always emits `_routing`; independently confirm live routed hits expose it or explicitly request that stored metadata before treating the routing guarantee as verified.

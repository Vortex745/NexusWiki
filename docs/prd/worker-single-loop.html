Worker 单环化 PRD

保留当前 Router，把 Worker 改成文章里的单环执行形态。不合并 Router 和 Worker。

依据：Claude 官方文章 Building agents: When to fold subagents into your main agent loop。 文中关于单 Agent 与 subagent 的对比结论来自 Anthropic 的内部工程经验，不是本项目的实测数据。

01背景与决策

当前主 Agent 循环只做意图判断。它没有文件读写和命令执行工具。任何需要动文件或跑命令的请求，都会被 dispatch_task 交给一个独立 Worker 会话。Worker 在自己的上下文里执行，结束后用一段文本汇报，Router 再把这段文本转述给用户。

文章的核心建议是把这类通用 subagent 折叠进主循环。折叠的条件是：单循环没有上下文膨胀导致的退化，任务不需要并行和可丢弃的新上下文，单循环能选对工具。文章同时说明，需要并行且上下文可以丢弃时，可以保留 subagent。

产品决策：不合并。Router 继续负责对话、判断和调度。Worker 继续作为独立执行上下文。保留的原因是后台执行和对话连续性。用户派发任务后可以继续聊天，Worker 在自己的上下文里跑完再汇报。这对应文章的第二个保留条件。

代价是 Router 看不到执行过程，只能依赖 Worker 的汇报。本 PRD 用三件事降低这个代价：Worker 写计划并在执行中修改，汇报工具在代码里校验产物，汇报改成固定结构。文章里的折叠步骤不采用。

可行性判断。技术实现没有硬阻塞，置信度 0.9。产品可行性 0.7。两个未知项决定成败：改造后质量是否不降，置信度 0.55；12 回合预算是否够用，置信度 0.5。前置探针和 10 任务评测负责回答这两个问题。下面是本次评审给出的判断估算，不是实测数据。

目标。把 Worker 从“能读写文件的会话”改成有纪律的单环执行 Agent。一个模型、一个上下文窗口、开放工具循环，带回合预算。流程放进技能，动作放进工具，参考资料通过任务输入或检索工具提供。Worker 仍然是通用执行器，不按领域拆分。

可观察结果。Worker 汇报时带上产物清单，清单由汇报工具在代码里校验。任务超过回合预算时，Worker 先收到一次收尾提醒，仍不汇报则停止并生成失败汇报，不静默停止。流程知识按需加载，不堆在系统提示词里。Router 的派发、任务行、叫停和恢复行为保持不变。

02范围

P0

  • Worker 的单环执行纪律：计划写在上下文里，工具结果原样回到同一上下文。
  • 渐进披露：流程进技能，动作进工具，参考资料走任务输入或检索工具。
  • 工具治理：按用户意图分组，工具定义保持在 30 个以内，不新增专家 Worker。
  • 回合预算与收尾提醒。
  • 结构化汇报与代码校验产物。
  • 任务上下文隔离：Worker 只接收任务指令，不继承主会话历史。
  • 三个前置探针。
  • Worker 改造的评测门禁。

P1

  • 多个后台任务并行。现有能力，不新增界面。
  • Router 的知识检索。现有 search_knowledge 行为不变。

不做

  • 不合并 Router 和 Worker。
  • 不给 Router 增加文件或命令执行工具，也不加核对工具。
  • 不为每个领域新增一个 Worker。领域能力用技能或工具表达。
  • 不改任务状态机和聊天时间线。running、done、failed、aborted、interrupted 保持原样。
  • 不新增审批门。当前 Worker 没有审批门，改造后保持一致。
  • 不先建技能库。首批只做两个技能，验证路径后再扩。

Router 与 Worker 的分工

职责RouterWorker
对话 拥有用户会话，负责理解和回复 不直接面对用户

04Worker 功能需求

FR-01

单环执行

触发
Router 调用 dispatch_task，启动一个 Worker 会话。
处理
  • Worker 在一个模型、一个上下文窗口里运行开放工具循环。
  • 首个回合写下计划，后续按工具结果修改计划。
  • 每个回合可以发出多个工具调用。独立调用并行执行，有依赖的调用串行等待。
  • 工具结果原样回到同一上下文，不经过摘要层。
  • 不跑固定多步流水线，不靠意图分类器决定下一步。
结果与状态
  • 任务完成后调用 report_result，汇报结果。
  • 会话结束但没有调用汇报工具时，按失败处理，沿用现有行为。
例外
  • 工具失败。Worker 在同一上下文里读取错误，重试或换方案。
  • 模型调用失败。汇报失败原因，沿用现有的错误落账。
  • 达到预算。按 FR-04 收尾。
FR-02

渐进披露

系统提示词
只写执行范围、工具使用规则和汇报契约。保持短小，不堆放领域流程。
技能
  • 步骤、规则和判断标准写进技能。系统提示词只放一句描述。
  • 完整内容在需要时加载，不常驻上下文。
  • 技能由 Worker 自己按任务需要使用，不由 Router 预先拼进提示词。
  • 首批只做两个技能。一个管文件修改，一个管命令执行。先验证加载和命中，再扩技能库。
工具
需要执行动作、读取实时数据或返回固定结构时，做成工具。工具描述写清触发条件，不写长篇说明。
参考资料
任务需要的参考资料由 Router 写进任务指令，或由 Worker 调用检索工具获取。不把整段资料粘进系统提示词。
禁止
不把领域流程写成新 Worker 类型。领域能力用技能或工具表达。
FR-03

工具治理

分组
工具按用户意图分组，不按单个 API 拆分。一个工具可以覆盖同一类动作。
数量
Worker 可用的工具定义保持在 30 个以内。文章的经验值是超过 30 到 50 个后工具选择开始退化。
当前工具面
Worker 使用现有文件读写、编辑和命令执行工具，加上 report_result。新增工具必须对应真实任务需求，不为假设场景预留。
扩展方式
需要新能力时，先判断它属于技能还是工具。两者都不适合时，再讨论是否保留独立上下文。不新增专家 Worker。
FR-04

回合预算与收尾提醒

预算
每个任务最多执行 12 个模型回合。一个回合可以包含一批并行工具调用。数值是起点，评测后校准。[Assumption, TBD]
计数
按模型回合计数，不按单个工具调用计数。一个回合里并发多个工具，仍算一个回合。
收尾回合
  • 第 12 回合作为收尾回合。进入收尾回合前，runner 发一次提醒，要求 Worker 调用 report_result。
  • Worker 可以在收尾回合里完成最后的写入和汇报。
  • 收尾回合结束仍未汇报，runner 调用 session.abort()，不再开新回合。
abort 后的汇报
  • runner 生成一条失败汇报，包含最后一条 assistant 文本和任务目录中的文件清单。
  • 汇报摘要写明“未完成：达到 12 回合预算”。
  • 不得静默停止，不得把未完成说成完成。
提前判断
计划阶段判断任务无法在预算内完成时，先汇报需要拆分，不要先做一半再停下。
FR-05

结构化汇报与代码校验产物

汇报字段
report_result 包含三项：
  • status：ok 或 failed。
  • summary：给用户看的一句话结果。
  • artifacts：产生或修改的文件路径列表，可以为空。
校验位置
  • 校验写在 report_result 的 execute 里，用文件系统检查，不靠提示词自觉。
  • 相对路径按任务目录解析。绝对路径必须落在任务目录内，越界路径按无效处理。
  • status 为 ok 时，每个 artifact 必须存在、可读，并且是文件。
  • 任一 artifact 缺失、不可读或越界时，工具返回错误，不记录汇报。Worker 可以在同一回合修正，或改报 failed。
  • status 为 ok 且 artifacts 为空时允许，summary 必须说明没有产生文件。
  • status 为 failed 时不做产物校验，允许列出部分产物。
Router 的处理
Router 继续按现有方式把汇报转成用户消息。汇报文本里带上产物清单。Router 不读文件，也不做二次核对。
用户看到
任务行只显示标题和状态。最终结果只在 Router 的回复里出现一次，不重复。
FR-06

任务上下文隔离

输入
Worker 只接收任务指令，不继承主会话历史。任务需要的背景由 Router 写进任务指令。
输出
任务结束后只保留汇报和产物文件。Worker 的中间上下文丢弃。
原因
保持新上下文，避免主会话膨胀。任务之间不共享隐式状态。下一次任务需要前一次结果时，由 Router 把结果写进新任务指令。
边界
Worker 不读 Router 的会话文件，不改任务表，不碰模型凭据和应用数据库。
FR-07

前置探针

目的
在全量改造前，用三个小实验验证技术判断里置信度最低的三处。任何一个探针失败，先修复或调整 PRD，不进入全量改造。
探针 A
预算截断。
  • 监听 turn_start 和 turn_end，按回合计数。
  • 收尾回合前发一次提醒，收尾回合结束仍未汇报则 abort。
  • 通过标准：prompt() 正常结束，任务落 failed，失败汇报里包含最后一条 assistant 文本和文件清单。
探针 B
技能加载。
  • 把两个技能放进独立目录，用显式路径加载，不扫描用户目录。
  • 通过标准：系统提示词只出现短描述，完整内容只在 Worker 调用 read 时加载。
探针 C
汇报校验与 Router 兼容。
  • 给 report_result 加 artifacts，用假 Worker 写一个文件。
  • 通过标准：文件存在时接受汇报，文件缺失时返回错误，注入 Router 的文本仍可用，任务行状态不变。
FR-08

评测门禁

金标任务
三个探针通过后，建 10 个端到端任务，覆盖以下场景：
  • 单文件创建。
  • 单文件修改。
  • 多文件修改。
  • 执行命令并读取输出。
  • 前序修改后的连续追问。
  • 知识库检索后执行。
  • 两个并行后台任务。
  • 后台任务失败。
  • 后台任务叫停。
  • 超过回合预算的长任务。
执行规则
  • 金标任务覆盖生产中会一起运行的每条链路，以及每条不能破的规则。
  • 每个任务跑两次。文章提到，某些回退只在两次中的一次出现。
  • 对比基线（当前 Worker）和改造后的 Worker。
  • 记录完成正确性、产物准确性、模型回合数、端到端延迟和工具选择。
  • 一次只改一类东西。顺序为汇报结构、技能加载、预算、并行工具调用。
  • 只要某个任务从通过变为失败，就先修复或回退这次改动，再进入下一项。
  • 不要只看总分。记录哪些任务发生翻转。
切换条件
改造后的 Worker 在 10 个任务上完成正确性不低于基线，且没有出现新的禁止行为，才作为默认 Worker。评测未通过时，保留现有 Worker 行为。
用户可见性
评测是迁移门禁，不是产品功能。用户不需要看到评测面板。

05共享规则与边界

规则定义
Router 不变 派发、任务状态、叫停、恢复和结果注入保持现有行为。Router 不获得文件或命令工具，也不加核对工具。
执行位置 Worker 是唯一执行文件和命令的地方。执行范围限任务目录。
返回通道 Worker 的汇报是唯一结果通道。中间过程不回传，除非写进 summary。
代码强制 预算计数、收尾提醒和产物校验由 runner 与汇报工具执行，不靠提示词自觉。
完成证据 artifacts 是完成证据。没有产物时，summary 必须说明。产物缺失或越界时不得报 ok。
任务状态 沿用 running、done、failed、aborted、interrupted。预算耗尽按 failed 落账，摘要写明未完成。
技能 技能放独立目录，描述短，按需加载。首批两个，验证后再扩。不把领域流程写进 Worker 系统提示词。
上下文 Router 拥有对话，Worker 拥有任务。两者不共享隐式状态。

06开放问题
